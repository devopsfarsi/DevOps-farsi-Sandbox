# راهنمای نگارش Template

این سند برای کانتربیوترهایی است که می‌خواهند یک Lab آموزشی (Template) طراحی کنند. ساخت Template یکی از ارزشمندترین نوع مشارکت‌هاست: هر Template جدید یعنی یک تمرین جدید برای همه یادگیرندگان.

پیش‌نیاز مطالعه: [05-template-specification.md](05-template-specification.md)

---

## 1. پیش از شروع

برای نوشتن Template لازم نیست متخصص زیرساخت باشید؛ کافی است به موضوع تمرین مسلط باشید (مثلاً Nginx، Docker، Kubernetes، Monitoring).

انتخاب موضوع خوب:

- یک مسئله واقعی و پرتکرار باشد (مثلاً «سرویس بالا نمی‌آید»، «Routing خراب است»)
- در یک جلسه 30 تا 60 دقیقه‌ای قابل حل باشد
- منابع کمی مصرف کند
- بدون اینترنت قابل اجرا باشد

## 2. مراحل کار

### مرحله 1 — ایشو پیشنهاد بدهید

یک Issue با عنوان `Template proposal: <name>` باز کنید و این موارد را بنویسید:

- موضوع و سناریو (داستان تمرین)
- سطح دشواری: easy / medium / hard
- مدت تخمینی
- مهارت‌های تمرین‌شده
- منابع مورد نیاز (CPU و Memory تقریبی)

بعد از تأیید، ایشو به شما Assign می‌شود.

### مرحله 2 — ساختار پوشه را بسازید

طبق سند 05:

```
templates/<name>/
├── template.yaml
├── manifests/
├── tasks/
├── tests/
└── README.md
```

### مرحله 3 — Manifestها را بنویسید

- فقط منابع لازم را تعریف کنید.
- همه‌چیز باید در Namespace ایزوله کار کند.
- به NetworkPolicy دقت کنید: Template نباید به سرویس‌های بیرونی وابسته باشد.

### مرحله 4 — Taskها و Validation را تعریف کنید

- Taskها مرحله‌به‌مرحله باشند و راه‌حل را لو ندهند.
- هر Task حداقل یک Check در بخش Validation داشته باشد.
- Checkها باید رفتار درست را بسنجند، نه فقط «فایل وجود دارد».

### مرحله 5 — README آموزشی بنویسید

ساختار پیشنهادی:

1. مقدمه — سناریو چیست و کاربر چه می‌کند
2. مفاهیم — دانش لازم برای حل تمرین
3. تمرین — شرح Taskها
4. اشاره به Hintها

### مرحله 6 — تست محلی

- قبل از PR، Template را در یک کلاستر محلی اجرا و Validation را تست کنید.
- انتخاب ابزار تست محلی (مثلاً k3d یا kind) جزو [تصمیم‌های باز](08-open-decisions.md) است (D-016)؛ فعلاً هر ابزاری که برای شما کار می‌کند کافی است.

### مرحله 7 — PR

- PR را به برنچ develop بفرستید.
- ایشو را لینک کنید و خروجی تست محلی را ضمیمه کنید.
- ریویو بر اساس چک‌لیست سند 05 انجام می‌شود.

## 3. مثال کامل: nginx-basic

کوچک‌ترین Template ممکن:

- **سناریو:** یک سرویس App ساده پشت Nginx قرار دارد؛ Reverse Proxy درست کار نمی‌کند و کاربر باید Configuration را اصلاح کند.
- **Taskها:** بالا آوردن سرویس → اصلاح Routing → پاسخ درست HTTP
- **Validation:** http-check روی مسیر مشخص با کد 200

نمونه template.yaml: [05-template-specification.md](05-template-specification.md)

## 4. قواعد کیفیت

- [ ] بدون وابستگی به اینترنت
- [ ] منابع کم (ترجیحاً زیر 512Mi Memory)
- [ ] Taskها به‌ترتیب سختی
- [ ] Hintها کمک‌کننده‌اند ولی راه‌حل لو نمی‌دهند
- [ ] Validation رفتار واقعی را می‌سنجد
- [ ] README فارسی و کامل است
- [ ] در محیط محلی تست شده

## 5. ایده‌های Template برای شروع

(پیشنهاد اولیه — با پیشرفت فازها تکمیل می‌شود)

- `nginx-basic` — Reverse Proxy ساده
- `broken-app-debug` — یک App که به‌خاطر متغیر محیطی اشتباه بالا نمی‌آید
- `k8s-deployment-fix` — Deployment که به‌خاطر Resource Limit در CrashLoop است
- `prometheus-setup` — اتصال Prometheus به یک سرویس و ساخت Dashboard ساده
